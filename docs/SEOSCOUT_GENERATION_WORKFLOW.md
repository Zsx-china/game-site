# SEOScout 文章生成工作流

本流程只处理本地文章生成。远端 VPS 完成搜索和采集后，先同步关键词、
`out/search_results.json` 与 `out/collected/`；翻译、站点导入和部署分别确认。

## 1. 提供商预检

1. 从提供商官方文档或 `/models` 确认当前端点和模型；凭据只写入私密 `.env`，不进入命令、仓库或日志。
2. 使用一个真实关键词执行：

   ```bash
   seoscout generate --keywords keywords.json --preflight --only "完整关键词"
   ```

3. 预检依次发送短控制请求和一份真实文章提示词，验证返回结构，但不保存文章。预检失败即停止，不启动批量生成。

验收：控制请求和真实文章响应均通过；命令返回 0；没有新增 MDX。

## 2. 小批放行

1. 精确生成一篇：

   ```bash
   seoscout generate --keywords keywords.json --only "完整关键词"
   ```

2. 检查实际 MDX 的 metadata、分类、正文结构、占位符和代码围栏；占位符采用与模板 `site:check` 相同的低误报规则：拦截 `XXXXX`（5 个以上 X）及独立大写 token `TODO`、`TBD`、`PLACEHOLDER`、`INSERT HERE`，不把正文中的普通小写单词 `todo` 判为占位符。再串行验证第二篇。
3. 两篇都通过后，以每批 1–2 篇运行完整生成。已有文章默认跳过，不使用 `--overwrite`。

### 快速指南与视频的内容准备

生成或编辑文章时，按 `docs/NEW_SITE_WORKFLOW.md` 第五部分“文章增强”执行，导入时复核。不假定 SEOScout 已自动支持这些字段；先检查实际输出，缺失时在本地对成功文章做小范围编辑，不为增加模块重新生成整篇或覆盖已成功内容。

- 有明确行动要点的攻略，优先在 MDX 的 `export const metadata` 中添加 `quickGuide: ["短要点", "含 **关键词** 的短要点"]`，通常 3–5 条。每条须有正文和来源支撑；无合适内容时省略，不把 QuickGuide 写进正文或目录。
- 视频仅在有经过核实且与文章主题直接相关的来源时添加：参考站的正文插入方式，在相关小节的说明、步骤或要点之后插入 `<VideoEmbed youtubeId="实际11位ID" title="准确的视频标题" />`，按内容关联选择位置，不固定放在文章开头或第一个 H2 之前，也不按固定屏数或段落数插入。不要把示意 ID 留在输出中。优先一个有用视频，不要求每篇都有；没有合适视频时不添加。记录原视频 URL、作者和文章目标位置，供导入时核验；不得复制其他游戏示例或虚构官方来源，也不下载音频或转写。
- 翻译时同步翻译快速指南和视频 `title`，保留同一来源的 `youtubeId`；视频内容不适合目标语言读者时重新评估是否保留。翻译仍需独立授权。

`--only` 可重复，且只接受项目 `search_results.json` 中的完整关键词；未知关键词必须返回非零状态。

## 3. 错误处理与续跑

- `401`、`402`、`404`：视为凭据、余额、端点或模型配置错误，立即停止后续批次。
- `429`：优先遵循 `Retry-After`；无该响应头时使用有上限的退避。连续限流后停止本轮，稍后续跑。
- `503`、`529`：使用有上限的指数退避；本轮失败项留待续跑。
- 超时或空响应：保留已成功文件，只补缺失项。进度必须分别显示成功数和失败数。

提供商切换时重新执行预检和两篇小批验证，不沿用旧模型假设。

## 4. 完成验收

递归核对 `articles/en/**/*.mdx`，不得只看命令退出码：

1. 实际文件总数与关键词总数相等，各分类数量相等。
2. 无零字节、重复、缺失或意外文件。
3. 每篇 metadata 位于文件开头，title、description、category 完整且 category 等于父目录。
4. 正文非空且有 H2；按上述统一规则无明确占位 token、残留代码围栏或模板说明。文章导入站点后立即运行目标站 `npm run site:check`，再进入导航或上线验收。
5. 记录提供商、成功数、失败项和未完成项；确认无生成进程残留后停止并汇报。
6. 逐篇核对新增快速指南的条数、加粗语法和事实支撑；视频 ID 为 11 位且标题非空，来源与插入段落相符。汇报实际带模块的文章及未添加原因，允许无合适来源时跳过。组件渲染、主题、移动端与播放配置按做站流程在目标站验收。

验收通过后才进入站点导入。翻译保持独立步骤，不因英文生成成功而自动执行。
